# 超声报告桌面质控软件设计

日期：2026-10-21。状态：会话方案已确认，本文待审阅。

## 1. 目标与交付

面向医院超声报告审核人员，在当前 Windows 电脑运行独立桌面软件。用户选择摄像头并框选报告区域，点击按钮或按快捷键拍摄一份完整报告，软件自动完成本地 OCR、字段整理、DeepSeek 文字质控、结果提示和本机留档。通过表示本工具未发现问题，不代表医院系统已签发报告。

本期交付可双击启动的桌面入口与本机可运行版本、配置说明和验证记录。重新配置当前电脑的 Python/OCR 环境；优先验证 NVIDIA GPU，提供 CPU 选项。暂不制作跨电脑通用安装包，不联动医院系统，不自动修改或签发报告，不分析超声影像作出诊断，不实现自动连续监测或多张合并。

样例目录包含腹部浅表、介入造影、心脏、血管四类。均支持导入测试，但不能将未标注截图当作医学正确答案。

## 2. 结构与接口

推荐 Electron + React/TypeScript 界面，Python 常驻工作进程负责 PaddleOCR 和本地记录。新应用放在工作区独立目录 `ultrasound-qc`，现有 PaddleOCR 源码保留，通过适配层调用已实现的版面、表格及文字识别能力。避免直接调用每次创建和关闭模型、打开浏览器的原入口流程。

Electron 主进程管理窗口、摄像头权限、快捷键、Python 子进程及 DeepSeek 请求。渲染层仅加载本地应用资源，关闭 Node 集成，开启上下文隔离和沙箱，通过白名单 preload API 访问应用功能。API 密钥不交给渲染层；设置页输入后交给主进程，使用操作系统支持的加密存储，不能安全加密时仅本次运行保留，不回退明文持久化。聊天中提供过的密钥不写入源码或文档。

Python 使用独立虚拟环境；固定验证通过的依赖版本并记录 Python、PaddlePaddle、PaddleX、OCR 模型版本。模型一次加载，多次复用；启动时展示初始化状态，退出时释放进程和设备。依赖兼容性与 GPU 支持在安装验证后记录，不能根据旧电脑说明直接宣称兼容。

Electron 与 Python 使用标准输入输出传递逐行 JSON 消息，标准错误专门输出诊断日志。每条请求和响应包含 request_id；支持初始化、识别、历史读取和退出，识别过程可报告阶段事件。图像通过本地文件路径传递。每次只执行一份质控任务，处理中禁止重复提交；失败任务可重试并保留尝试记录。

核心数据约定：

- Capture：任务编号、采集时间、输入来源、原图路径、裁剪图路径、归一化 ROI。
- OCRDocument：有序文本块和表格；块/单元格包含稳定编号、原文、图像位置及可获得的识别置信度。不得把缺少置信度解释为高置信度。
- QCPayload：检查部位、所见、测量表和结论。保留单位、表头、左右侧及原始编号；不发送年龄、性别、身份信息或图片。
- QCResult：状态、摘要和问题列表。每项问题包含类别、严重程度、对应源编号、原文摘录、原因和建议；无法确定的修改建议可以为空，并明确需人工复核。
- Record：关联采集、原始 OCR、实际外发文本、模型/提示词版本、结果、各阶段耗时和历次尝试，不保存密钥或认证头。

## 3. 用户流程与结果规则

主界面提供采集、当前结果、历史、设置入口。采集区支持摄像头选择、预览、框选/重置 ROI；切换设备或分辨率后要求重新确认 ROI。默认快捷键 Ctrl+Shift+Q，仅应用窗口内生效，输入框编辑时不触发。提供图片导入，以便无摄像头时也能验证整条流程。

拍照后先保存本地原图，再裁剪识别区域。显示采集、OCR、字段整理、模型质控、保存阶段，界面保持可操作。原图可查看；识别报告与问题列表并排展示，点击问题定位对应段落/单元格。保留最初识别文字；用户校正文字后重新质控形成新尝试，不覆盖最初记录。

只向 DeepSeek 发送允许的四类内容，以白名单字段构建请求，再过滤可能混入正文的姓名、证件号、就诊号、联系方式、年龄和性别信息。不直接发送整份 OCR 或隐藏调试上下文。字段提取含糊时暂停外发，让用户核对发送预览，不以未经确认的整份 OCR 作为兜底。

检查部位或所见/结论无法辨认、正文空白、明显截断、表格对应关系无法确定时标记需核对，提供重拍和编辑入口。仅靠单个置信度或清晰度分数不能证明报告完整。无测量表不属于失败；无清晰表格线的测量内容允许按行列结构表达，不能猜测缺失数值或强行错配单元格。

质控覆盖错别字、缺漏字、多字、单位、数量级、左右侧/器官/数值/所见与结论之间的内部矛盾。缺少年龄、性别或其他必要信息时不得推断相关医学结论；需要这些信息才能判断时报告信息不足。没有医院规则或指南依据时不硬编码通用正常值范围，不把异常检查结果本身当作文字错误，不自动补写诊断。

结果状态：

- 通过：OCR 和必要字段检查通过，模型返回有效且完整的结构化结果，没有问题及待复核事项，记录落盘成功。
- 发现问题：有明确问题；播放一次提示音并显示原文、原因、建议。允许关闭声音、调整音量及测试声音，原图不自动改写。
- 需人工复核：存在 OCR、结构、医学判断或信息不足方面的不确定项；明确展示原因，不能标绿放行。有明确问题并伴随不确定项时整体为发现问题，同时保留待复核项。
- 处理失败：模型超时、无效密钥、网络错误、返回格式不合格、进程异常或保存失败。保留具体阶段与可操作的重试入口，不能记录为通过。

模型输入中的指令视为报告内容，不执行。采用 JSON 返回并做本地结构、枚举和源引用校验；声明通过但含问题、摘录与源文本不符或引用不存在时不能通过。接口地址/模型在设置中可配置，默认仅使用官方 DeepSeek HTTPS 接口；首次联通确认可用模型并保存型号，不依赖历史模型别名永久有效。请求超时默认 90 秒，不自动反复重发，用户可手动重试。

## 4. 本机记录与配置

默认数据存储在当前用户 LocalAppData/UltrasoundQC，SQLite 保存记录索引与结构化结果，按任务目录保存原图、裁剪图、OCR JSON 和文字。完整 OCR 及照片仅存本机；不因完整留档而扩大外发范围。历史可按时间、结果筛选，查看原图、OCR、问题和重试记录。默认不自动删除，可由用户明确操作删除选定记录，删除前确认。

密钥、日志、模型权重、运行环境、医院样例和完整报告数据不纳入版本控制。诊断日志避免报告正文及密钥，展示错误类别而不是原样输出包含认证信息的请求。OCR 适配器不能继续向原仓库 inference_results 隐式写出另一份未管理记录。

## 5. 验收与限制

1. 在本机重新建立 OCR 环境，记录真实运行设备和依赖；用代表性段落、心脏表格、血管测量及介入造影样例确认结构化结果。单独记录 CPU/GPU 中实际验证通过的路径。
2. 验证鼠标拍照、窗口内快捷键、ROI 坐标映射、图片导入、摄像头不可用、分辨率变化、重复点击和软件重启。
3. 用构造的确定性案例验证错漏多字、单位与量级、左右侧矛盾、所见与结论矛盾，以及异常结果不等于报告错误。医学正确率需将来由医生标注的独立数据集评估。
4. 通过捕获实际请求验证只包含允许字段，不包含图片、年龄、性别、身份信息；不确定提取会暂停外发。
5. 验证空 OCR、残缺结构、断网、超时、错误密钥、无效 JSON、错误引用、通过状态冲突、工作进程退出和保存失败均不会被标记通过。
6. 验证提示音、问题定位、修改文字后重新质控、历史完整留档、删除、密钥存储和关闭退出释放资源。
7. 验证双击入口打开独立窗口且不启动浏览器；报告模型初始化、OCR、模型请求及整体耗时，避免承诺未经测量的响应时间。

开发顺序：环境与单图 OCR 验证 → 桌面外壳/采集 → 结构化与外发过滤 → DeepSeek 质控 → 留档与历史 → 异常路径与本机打包验收。
