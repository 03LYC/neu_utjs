## 使用

入口位于工作区根目录 **超声报告质控.lnk**，也可双击 **启动超声报告质控.cmd**。2026-10-23 已完成迁移恢复，正式打包版窗口、GPU OCR 和 DeepSeek 连接均已验证。启动入口会先设置项目内的缓存目录，再启动程序。恢复记录见 `MIGRATION-2026-10-23.md`；`HANDOFF.md`、`VALIDATION.md` 中 2026-10-21 的拦截记录属于历史状态。

1. 在“设置”页本机输入 API 密钥，保存后点击“测试连接与模型”。密钥通过 Windows 加密保存，不显示原值。可选择 GPU/CPU 并预加载 OCR 模型。
2. 在“报告质控”页打开摄像头，选择设备；或导入现有报告图片。框选完整报告区域，确保检查部位、所见、测量和结论齐全。
3. 点击“拍照并质控”，或在窗口内按 Ctrl+Shift+Q。处理期间不重复提交。首次模型加载/下载较慢，后续重复使用已加载模型。
4. 识别不可靠或分区含糊时，先对照原图和发送预览核对。可编辑识别文字、用“新增文本段落”补录漏识别内容后重新质控，也可“暂不发送，留待复核”。摄像头切换或分辨率变化后，需重新框选或确认全画面；断连后禁止采集旧画面。
5. 通过、发现问题、需人工复核、处理失败分别记录；发现明确问题播放提示音。点击问题摘录定位文本单元，修改建议由医生在原系统确认使用。
6. 历史页面查看原图、原始OCR、每次发送四字段和质控结果。删除按钮会二次确认，删除无法撤销。

## 数据和隐私

默认 `%LOCALAPPDATA%/UltrasoundQC` 保存 SQLite、任务目录中的原始照片/裁剪图、OCR和结果；不自动删除。`paddle-ocr.json` 与 `ocr-full.txt` 保留原始模型输出和完整文字，`ocr.json` 与 `ocr.txt` 保留初次结构化报告，后续修订按尝试留存。密钥保存在该目录的 `api-key.enc`，使用操作系统加密；不可加密时只在内存保留。

只向官方 DeepSeek HTTPS 接口发送筛选后的 **检查部位、所见、测量表、结论**。图片和完整原文仅存本机，实际发送内容可在历史中核对。发现身份字段的表格会整体隔离，正文去除个人信息后需要核对完整性；没有标签的自然语言人名不能承诺自动识别，需要用实际院内模板验证过滤。程序不能证明OCR绝对完整或医学判断绝对准确；证据不足时要求人工复核，异常病理结果本身不等于文字错误。

本版本依赖本地 `.venv`、`.runtime/python`、`.runtime/models` 及相邻 PaddleOCR 源码。不要单独复制 exe 到其他电脑使用，也不要删除它旁边的 resources 等文件。下载、安装工具及缓存统一在本项目 `.runtime` 下；历史数据仍使用上面的原数据目录。

## 开发与运行

构建需要 Node.js。`scripts/setup-ocr.ps1` 会将 uv 和 Python 3.11.15 安装到项目 `.runtime` 下，修复复制后失效的虚拟环境，并优先复用现有依赖。默认 Paddle GPU 3.3.1 CUDA12.9，`-Cpu` 用于建立 CPU 环境。已存在 GPU 版环境使用CPU推理只需在软件设置选择CPU，避免在同一环境并装CPU/GPU两个发行包。

```powershell
. .\scripts\local-env.ps1
powershell -ExecutionPolicy Bypass -File scripts/setup-ocr.ps1
npm.cmd ci
npm.cmd start
```

验证：`npm.cmd run typecheck`、`npm.cmd test`、`.venv/Scripts/python.exe -m pytest python/tests -q`（设置 PYTHONPATH 指向现有 PaddleOCR 源码）、`npm.cmd run test:e2e`。端到端使用独立临时目录、合成报告和模拟摄像头，不等于实物摄像头或真实模型质控验收。

打包：`powershell -ExecutionPolicy Bypass -File scripts/package.ps1`。安装及模型下载需要网络，软件不自动升级。实际版本见 `python/requirements.lock.txt`、`package-lock.json` 和 `VALIDATION.md`。

## 常见问题

- 摄像头打不开：检查 Windows 隐私设置、USB连接、是否被其他软件占用，或先导入图片。
- 模型初始化慢：首次需要下载多个模型，等待完成；缓存会复用。官方 BOS 下载被阻断时检查网络。
- GPU错误：在设置中选择CPU，保存并预加载。GPU/CPU验证情况见验收记录。
- API错误：确认密钥、额度和连接测试。网络/超时不会标为通过，也不会自动重复收费请求。
- 后台进程退出：重新启动软件；未完成记录会标为失败，可以在历史中重试。

详见项目根目录 `docs/superpowers/` 中已确认设计与实现计划，开发状态见 `PROGRESS.md`，需人工处理事项见 `HANDOFF.md`。
